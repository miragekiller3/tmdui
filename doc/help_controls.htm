  2. Combox
    1. 实现
      1. comb拥有一个父窗口(任意，建议edit，非必须)，一个列表框(listbox或tree，必须)，一个列表框的window(非必须)。
      2. comb中listbox选择后，list内容会提交到父窗口上。
      3. 如果同时指定了poplist和popdlg，comb会创建一个新弹出窗口作为下拉列表。
      4. 如果只指定了poplist，则使用指定窗口作为下拉列表。
    2. 下拉框定位
      1. 下拉框的定位由参照控件(refer)决定，编辑器中的Refer属性可以设置参照控件的objid或id，默认为edit控件(Refer属性为0)。
      2. 下拉框左右margin边框与refer控件左右margin边框重合。
      3. 下拉框的上margin边框值等于refer控件的下margin边框值。
      4. 高对比度模式下下拉框margin值自动改成0。
      5. 如果下面空间不够，下拉框会朝上弹出。此时2个magin边框反一下，规律同上。
      6. 如果下拉框设置了autowidth、MaxWidth、MinWidth并且这些属性起了作用，则下拉框的一条margin边框与refer控件的其中一条左右margin边框重合，具体是左边还是右边由下拉框layout属性决定。
      7. 如果下拉框拥有autoheight和LAYOUT_VNONE属性，那么下拉框在往上和往下弹出时会自动处理纵向对齐。
      8. 如果refer属性设置了一个无效的objectid，比如说-1，那么combox不会自动定位，用户可以在WM_COMMAND+CBN_DROPDOWN消息中自己移动下拉框到指定位置。
    3. 通知消息(WM_COMMAND)：
      弹出下拉列表前：CBN_DROPDOWN。
      单击列表或者按下回车键：BN_CLICKED -> CBN_SELCHANGE -> CBN_SELENDOK -> CBN_CLOSEUP。
      取消弹出列表：CBN_SELENDCANCEL -> CBN_CLOSEUP。
      列表不弹出，按上下箭头键，鼠标滚轮：CBN_SELCHANGE -> CBN_SELENDOK。
    4. style：
      CBS_CLICKTOPOP：鼠标点击edit弹出下拉列表。否则只能点击按钮弹出。
      CBS_ARROWTOPOP：上下键弹出下拉列表。
      CBS_SPACETOPOP：空格键弹出下拉列表。
      CCB_FILTER：当edit内容发生改变时发送CCB_FILTER消息。
      CBS_NOIMEDIALTY：下拉列表上按上下键不会立即提交到edit上。
      CBS_NOEDIT：不需要父窗口，列表内容提交到控件自己。
    5. Combox例子见sample/Combo

  3. window
    1. DefaultItem
      1. 当窗口创建时，DefaultItem会转成default focus。窗口显示时，default focus会变成真正的focus。
      2. 窗口上的按钮如果是DefaultItem，则在焦点处于其他非按钮控件上时，按钮会显示成focus状态。（windows标准）
      3. 如果DefaultItem设为0或者无效值，则窗口创建时不设置默认焦点。
      4. 如果DefaultItem指向一个隐藏或者disable的控件，默认焦点会指向下一个控件。
    2. 图标
      1. 图标分为窗口左上角显示的图标、任务栏图标、Alt+Tab显示的图标3种。
      2. Alt+Tab图标用windows API::WM_SETICON+ICON_BIG设置。
      3. 任务栏图标windows API::WM_SETICON+ICON_SMALL设置。如果没有设置则使用Alt+Tab图标。
      4. 窗口左上角图标在属性frame::SysBk设置。如果没有设置则使用任务栏图标。
      5. frame::SysBk支持active、非active 2态。其他2种图标只支持1态。
    3. 窗口主题
      1. eThemeTypeSystem：窗口不使用编辑器中指定的frame，而是使用系统的窗口边框。子窗口，layered窗口，blur窗口不支持这种类型。
      2. eThemeTypeXP：经典窗口类型。子窗口或者操作系统在win7以下的普通窗口使用此主题。
      3. eThemeTypeLayered：用于半透明窗口，编辑器中要设置WS_ADV_LAYERED属性。
      4. eThemeTypeDWM：win7以上并且开启了DWM，特点是窗口带一个阴影。
      5. eThemeTypeDWMBlur：毛玻璃窗口。win7以上并且开启了DWM，编辑器中要设置DS_DWMBLUR属性。
      6. eThemeTypeDWMTransparent：用DWM实现的半透明窗口。win10以上并且开启了DWM，编辑器中要设置WS_ADV_LAYERED属性但是不能设置DS_NODWMTRANSPARENT。
      CTuiWindow::GetThemeType可以得到当前窗口主题类型。
      如果编辑器同时设置了WS_ADV_LAYERED和DS_DWMBLUR，窗口默认会先尝试加载毛玻璃效果，如果不成功，则加载半透明窗口。
      毛玻璃实际效果是窗口生成的背景位图的像素alpha值与系统毛玻璃管理器进行混合。
      因为系统不一定支持毛玻璃，所以对于毛玻璃效果要进行预防性处理: 
      ATResult CDlgXXX::OnInitDialog(ATUInt uMsg, ATWParam wParam, ATLParam lParam, ATBool& bHandled)
{
    EThemeType eType = this->GetThemeType();
    if (eType != eThemeTypeBlur)
        this->SetBkPic(IDC_BMP_NORAML);
    bHandled = false;
    return 0;
}
    4. 半透明窗口背景
      因为每次渲染都要把背景的alpha通道清除，所以半透明窗口背景图必须是srccopy属性。否则窗口阴影会不停地叠加变黑。
      带layered，DWMBlur，DWMTransparent属性的window和float控件都是半透明窗口。
      color类型的pic天然带srccopy属性，其他类型pic用srccopy属性勾选。
    5. 半透明窗口阴影与高对比度模式
      半透明窗口在高对比度模式下会变成不透明，此时窗口阴影会变成窗口颜色。所以会感觉窗口变大了。
      为解决这个问题，用window的margin属性来表示窗口阴影宽度。高对比模式下会自动把窗口缩小。注意：
      1. margin值必须为负数。
      2. window必须设置frame。

  4. 快捷键及hotkey控件
    1. 按钮自带属性"hotkey"，可以为按钮增加热键功能。其生命周期与按钮的生命周期一致。
    2. 菜单未来会实现自动关联快捷键，目前还不支持。
    3. 每个hotkey控件里可以存放10组热键，热键的生命周期也与控件一致。
    4. 热键有3种模式：当前对话框有效，当前应用有效(app)，整个操作系统有效(sys)。
    5. 键盘响应顺序依次为sys->app->其他进程的sys->控件->对话框热键.
    6. sys热键当发生两个进程争抢时，前台进程生效。（不像windows的hotkey，重复注册热键注册不成功）
    7. 根据windows标准，sys与app热键优先级高于控件。例：设置热键'A'，当在edit中输入'A'时，热键生效，edit中无法输入字符。
    8. 热键触发后会在热键所在的对话框收到WM_COMMAND消息。
    9. windows下用vc生成的accelerator因为不跨平台，未来可能会取消支持。

  5. webview控件
    1. webview可以使用微软chrome或者IE引擎显示网页。
    2. chrome引擎运行环境配置：
      1. 安装微软最新版edge浏览器。
      2. 打开https://developer.microsoft.com/zh-cn/microsoft-edge/webview2/，选择“常青版引导程序”下载并安装。
      3. 解压源代码目录下的import.rar。
      4. 把import->webview->runtimes下的相应WebView2Loader.dll拷贝至程序运行目录。
      5. 确保程序运行目录有写权限。如果没有权限，要响应CWV_ONCRGETFOLDER消息指定userData目录。
    3. 属性：
      1. DM_NODELAYLOAD: 不使用延迟加载。默认为延迟加载，当控件及所有父控件都为visible时才创建对象。
      2. WVS_NOCHROME: 不使用chrome内核。
      3. WVS_NOIE: 不使用IE内核，如果2个属性都不勾选，控件默认先尝试加载chrome，不成功则加载IE。
      4. WVS_NOSCRIPT: 禁止控件调用脚本。
      5. WVS_EXTENDMODE: 扩展模式。这个模式下支持各种回调事件。
      6. WVS_EXTNOCONTEXTMENU: 关闭默认右键菜单，但是会发送WM_CONTEXTMENU消息。仅支持扩展模式。
      7. WVS_PRIVATEMODE: 私有模式。
      8. 以上属性可以在WM_CREATE或以前改变。之后再改无效。
    4. 回调消息：
      1. CWV_ONOBJINIT: 由于chrome是异步内核或者延迟加载，所以在OnCreate的时候不保证拿到接口，必须在此消息后才能QueryControl。
      2. CWV_ONGETFOLDER: 为用户自己发布chrome引擎指定执行目录和数据目录，可以指定2组，空为系统默认。顺序为0,1。
      3. CWV_ONCR开头的消息仅支持chrome内核。
      4. CWV_ONIE开头的消息仅支持IE内核。
      5. 其他以CWV_ON开头的消息同时支持2个内核。
      6. tmdui.h中回调消息定义的地方可以看到相关帮助。
    5. _tuiApp::SetWebview2XXX系列函数可以设置chrome引擎的一些全局属性。
    6. 函数QueryControl可以取得如下内核接口:ICoreWebView2Environment, ICoreWebView2Controller, ICoreWebView2, IWebBrowser2。
    7. 控件还封装了一批2个内核通用的函数，如Navigate。
    8. SetExtUnkown函数可以实现自定义的IDocHostXXX,IOleCommandTarget,IDispatch接口(IE内核)。
    9. 控制弹出窗口(仅扩展模式)： 
      ROUTE_ID_HANDLER(IDC_IECONTROL, CWV_ONNEWWINDOW,    OnNewWidnow)
ATResult OnNewWidnow(int idCtrl, AT::TUIMSG* pMsg, ATBool& bHandled)
{
   模式1：return true; // 阻止弹出窗口
   模式2：return false; // 默认,在新的浏览器中打开url.
   模式3: *(AT::HTUI*)pMsg->lParam = hWnd; return false; // 在指定Webview中打开url. 可以是自己.
}
    10. 编程建议：
      1. 不应该依赖DocumentComplete事件。替代方案是函数AddScriptToExecuteOnDocumentCreated(javaScript)。
      2. 不应该直接对dom进行读写操作。替代方案是函数ExecuteScript(javaScript)。
      3. html向容器发送消息，推荐使用“window.chrome.webview.postMessage(json字符串)”，不建议IE版的external模式。
      window.chrome.webview.postMessage("{\"Key\":\"test1\",\"Value\":{\"X\":1,\"Y\":2}}"); // 正确，IE内核扩展模式及chrome内核;
window.chrome.webview.postMessage({"Key":"test1","Value":{"X":1,"Y":2}});             // 避免，直接传json对象不支持IE内核;
window.external.postMessage("{\"Key\":\"test3\",\"Value\":{\"X\":3,\"Y\":4}}");       // 避免，只支持IE内核;
      4. 容器向html发送消息，推荐ExecuteScript函数。不推荐chrome的PostWebMessageAsJson，因为不通用。
      5. 无论是容器向html发消息，还是html向容器发消息，都是异步操作。
    11. 在网页中判断是webbrowser还是webview控件: 
      if (typeof window.chrome != "object")
    this is webbrowser;
else
    this is webview;
    12. IE内核的网页中调用"document.write"会冲掉所有的js，造成window.chrome.webview.postMessage失败。
    13. 微软规范：不同配置的webview2控件使用相同的user目录会创建失败。（配置指_tuiApp::SetWebview2XXX函数）
    14. webview例子见sample/IEBrowser。

  6. progress, up-down, track-bar
    1. 用户输入改变控件pos前会发送CM_POSCHANGING消息，可以在这个消息中更改pos值，可以把pos新值改成跟旧值相同。
    2. 用户输入改变控件pos完毕通知消息为WM_COMMAND + SB_ENDSCROLL(鼠标拖动时还会收到SB_LINEUP,SB_PAGEUP,SB_LINEDOWN,SB_PAGEDOWN,SB_THUMBPOSITION,SB_THUMBTRACK)。
    3. 任何方法改变控件pos都会产生通知消息WM_COMMAND + CN_VALUECHANGE。
    4. 异步设置pos方法1(例：设置操作系统音量)： 
      ROUTE_OID_HANDLER   (IDC_TRACKBAR, CM_POSCHANGING, OnPosChanging)
...
ATResult CMain::OnPosChanging(int idCtrl, AT::TUIMSG* pMsg, ATBool& bHandled)
{
    int old = pMsg->wParam;
    int* pnew = (int*)pMsg->lParam;
    PostSetSystemVolume(*pNew); // 异步设置系统音量
    *pnew = old;                // 让控件维持原来的pos
    return 0;
}
void CMain::OnSystemVolumeChanged(int pos) // 系统音量回调
{
    CTuiTrackBarCtrl(Item(IDC_TRACKBAR)).SetPos(pos); // 等系统音量设置完毕后再把pos同步到控件上
}
    5. 异步设置pos方法2：
      在编辑器中建立2个trackbar控件，位置重叠。
      前面控件设置成鼠标穿透，后面控件前景图和背景图设置成透明。
      响应后面控件的WM_COMMAND + SB_XXX，得到控件的pos，用pos设置系统音量。
      在系统音量回调中，设置前面控件的pos。

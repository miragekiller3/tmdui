  1. AT库概览
    1. 本库包含了TM、DUI、GX三大模块。
    2. TM为基本库，包含了调试，线程，文件，字符串，时钟，定时器，GDI等基本模块。
    3. GX为图形渲染库，内核可动态切换为GDI、Direct3D、OpenGL。
    4. DUI为UI库，有以下特色:
      5. 1. 消息机制与windows相同。
      2. 接口与ATL兼容。
      3. 渲染使用GX库，支持内核动态切换。
      4. 支持HIDPI，多屏幕，高对比度，暗黑模式。
      5. 支持MSAA，UIA。
      6. 支持svg动画。
      7. 支持动态语言切换，动态换肤。
      8. 自带所见即所得的编辑器及功能强大的调试工具。
    5. DUI与GX不支持多线程，所有的DUI函数，除了PostMessage外，都不能跨线程调用。
      不支持多线程的意思是：load TMDui dll，LoadXml，Create等操作都必须在同一线程内。
      如果想在其他线程中与主线程交互，第一种方法：CTuiWidget::PostMessage。第二种方法：使用Callxxx系列函数，把跨线程调用转成主线程调用，此函数支持Lambda语法。
    6. DUI不对传入参数作出校验，也就是说，如果传入的HTUI句柄是无效的，代码可能崩溃。
    7. DUI函数和消息定义处一般都有简单的帮助，另外，由于DUI与ATL接口兼容，大多数帮助可以在MSDN上找到。
    8. 使用中如果觉得TMDUI有Bug，请联系作者进行控诉，尽量不要用奇技淫巧来回避问题。

  2. DUI编程如何避坑
    1. 尽量减少成员变量：
      避免 推荐 
      class CFoo {
    CTuiWidget m_wnd1;
    void foo() {
        m_wnd1.Show();
    }
};

      class CFoo {
    // CTuiWidget m_wnd1; // 不要缓存控件句柄
    void foo() {
        Item(id).Show(); // 需要时才实时获取
    }
};
    2. 坚持即用即建。视觉上不可见的控件，最优选项是destroy掉。
      不推荐hide。会有无谓的layout、广播消息、Accessiblity、动画，降低item函数效率。
      比较糟糕的选项是把控件大小改成0，同上。
      最糟糕的做法是用其他控件盖住，因为盖住了也还是会参与渲染和tabstop。
      虚假不可见控件可以通过MSAA hack到，产生安全隐患。
    3. 尽量不要调用ChangFrame、SetFocus、InvalidateRect、UpdateWindow、SetForegroundWindow这类残害系统自然和谐的函数。
    4. 尽量不要自己MoveWindow，充分利用DUI的Layout属性，或者arrow控件。阿拉伯语中MoveWindow很容易发生坐标计算错误。
    5. 代码尽量和资源放在一个模块。
    6. 单个资源释放应该调用unloadxml()。全部资源释放应该调用Term()。
    7. Term()函数必须调用，但是禁止写在dllMain的ProcessDetach中，必须在exe的释放函数链中调用(dll Detach前)。
    8. 切换DUI版本后一定要用那个版本的编辑器打开资源文件再保存一遍，千万不要手工merge。否则会发生不可描述的事情。
    9. 由于渲染优化，响应WM_PRINTCLENT不允许设置bHandled=false；否则此消息只会响应一次。
    10. 窗口自绘不要忘记支持高对比度和暗黑模式。
    11. 响应WM_DESTROY和WM_NCDESTRY必须设置bHandled=false；
    12. 基于优化，很多属性在paint后才能拿到正确值，比如说窗口rect，scroll，rich文字位置，tree item位置信息等，请注意鉴别。
    13. 不要在dllmain中创建UI，应该在LoadDll返回后再创建。

  3. 调试
    1. TM调试宏TM_DBG，默认在debug模式下打开，在Release模式下关闭，在工程设置中加入此宏可以强行打开调试模式。
    2. 没有TM_DBG宏将关闭以下功能：tmAssert，tmTrace，tmVerfiy(校验函数返回值)，InstanceCheck(内存泄露)，Analysis(性能分析)。
    3. DUI调试宏TM_PROTECTED，默认release模式下打开，在debug模式下关闭。作用是调用CTuiWidget函数时，如果wnd值为0，则直接返回，防止代码崩溃。
    4. 多模块编程中，不同的DLL使用不同的调试宏并且互相引用不会造成程序问题。
    5. 在自己的类中加上public: TM_CLASS_INSTANCE_CHECK(类名);可以自动检查此类是否内存泄露
    6. DUI提供了一个调试工具：
      在bin\uidesign目录下找到TMDui.dll，或者用TMDui_DebugTool.sln自己编译一个dll。替换掉应用程序的TMDui.dll即可。
      可以在运行中动态查看和编辑DUI控件、资源、事件，及其他强大功能。
    7. 简单的方法查看内存泄露：
      把调试工具拷贝到应用程序目录下，替换掉原配的TMDui.dll。
      启动程序，用VC调试进去。或者打开第三方trace查看工具。
      退出程序，查看调试工具打印的内存泄露trace信息。
      退出时断点下在tmdebug.cpp::~CDebugLeak()，中断后看m_aInfo.items.m_addrCallStack，右键加载符号文件，可看到内存分配时的调用堆栈。
      如果既没有看到泄露，也没有看到“no object leaks”这句话，那就是退出过程中发生了异常，dll未正常卸载。

      ROUTE_HANDLER   (CM_HINTONADDTOOL, OnHintAddTool)

ATResult CMain::OnHintAddTool(int idCtrl, TM::DUIMSG* pMsg, ATBool& bHandled)
{
    TOOLINFO* p = (TOOLINFO*)pMsg->lParam;
    CTuiWidget((TM::HTUI)pMsg->wParam).Item(IDC_STATIC_1000).SetWindowText(p->lpszText); // 将文本同步到tooltip
    return 0;
}

ATResult CMain::OnHintShow(int idCtrl, TM::DUIMSG* pMsg, ATBool& bHandled)
{
    WINDOWPOS* wp = (WINDOWPOS*)pMsg->lParam;
    ResetPos(wp); // 把tooltip移动到指定位置
    return 0;
}

void ResetPos(WINDOWPOS* wp)
{
    TM::CRect rc;
    ::GetWindowRect(wp->hwnd, &rc);
    POINT pt;
    GetCursorPos(&pt);
    rc.MoveToX(pt.x - rc.Width() / 2);
    rc.MoveToY(pt.y + 20);
    wp->x = rc.Left();
    wp->y = rc.Top();
    wp->flags &= ~SWP_NOMOVE;
}

  9. 自动宽/高度(window,widget,float)
    10. 当父控件拥有LAYOUT_AUTOWIDTH(HEIGHT)属性并且子控件拥有ALIGN、FOLLOW布局属性时，子控件会在完成布局计算后自动调整父控件位置和大小。
      例如：align left的子控件集合计算完布局后，DUI算出第一个align left子控件左边框减左marge位置是-10，最后一个align left子控件右边框加右margin是100，得到长度110。然后根据这个值更改父控件的scroll width。
      align left、right可以调整父控件宽度，align top、bottom可调整父控件高度，align client不可调整。
      子控件算出理论长宽后，向父控件发送CM_SETSCROLLRANGE消息，父控件在收到这个消息后异步movewindow。
    父窗口 子窗口 父窗口高度 父窗口宽度
    autoheight ALIGN_TOP_XXX 所有ALIGN_TOP_XXX的子窗口高度相加 n/a
    autoheight
    autowidth    		 同上 同上 所有ALIGN_TOP_XXX+autowidth的子窗口宽度最大值
    autoheight ALIGN_BOTTOM_XXX 所有ALIGN_BOTTOM_XXX的子窗口高度相加 n/a
    autoheight
    autowidth    		 同上 同上 所有ALIGN_BOTTOM_XXX+autowidth的子窗口宽度最大值
    autowidth ALIGN_LEFT_XXX 所有ALIGN_LEFT_XXX的子窗口宽度相加 n/a
    autowidth
    autoheight    		 同上 同上 所有ALIGN_LEFT_XXX+autoheight的子窗口高度最大值
    autowidth ALIGN_RIGHT_XXX 所有ALIGN_RIGHT_XXX的子窗口宽度相加 n/a
    autowidth
    autoheight    		 同上 同上 所有ALIGN_RIGHT_XXX+autoheight的子窗口高度最大值
    autowidth
    autoheight    		 同时存在横向和纵向ALIGN 所有纵向ALIGN的子窗口高度相加(忽略子窗口自动宽度) 所有横向ALIGN的子窗口宽度相加(忽略子窗口自动高度)

    注意事项：
    1. FOLLOW属性的子窗口只能让父窗口自动高度，不能让父窗口自动宽度。
    2. 父控件的调整方向跟子控件的align方向无关，父控件根据自己的的锚定情况来决定往哪个方向拉升或缩小。
      例如：如果父控件是靠右的，那么就是移动父控件的左边框，如果父控件是靠左的，那么就是移动父控件的右边框。如果父控件是居中或者frame的，则使父控件向两边同时收缩或者扩张，跟子控件是否align left、right无关。
    3. 自动大小支持dialog，并且这种调整也符合注意事项b：
      例如：如果用户希望对话框自动调整时保持底部坐标不变，那么可以设置dialog的layout属性为align bottom或者anchor bottom。
    4. 自动大小支持递归调用：第5层子控件决定第4层子控件，第4层子控件决定第三层子控件...，直到dialog。
    5. 不推荐自己响应size消息来手动move父控件。
    6. align client的意思是自己的大小由父控件决定，自动宽/高度的意思是自己的大小由子控件决定。这两者逻辑上互相矛盾，所以align client属性不会影响父控件的自动宽/高度。
    7. static，button的自动宽/高度由控件内容决定，跟子窗口无关。

  13. 绑定窗口
    • 绑定窗口是用复杂的窗口来显示一个简单的物件。
    • 绑定窗口目前有4个应用：显示listbox item，显示tree item，rich控件显示item，窗口转ITuiPic。
    • list和rich可以用XXXBindItemWindow系列函数绑定窗口。
    • rich可以用HTML之扩展"widget"标签来实现窗口绑定: "<widget src='object id' /> "。
    • 任何窗口调用函数ConvertToPic后，可以把ITuiPic指针传给任何可以使用ITuiPic渲染的地方，例如button的forepic。
    • 绑定窗口的原理是在要画的时候把窗口移动到那个地方，然后进行渲染。
    • 绑定窗口不在全局窗口列表内，所以不能用Item函数拿到窗口句柄，tabstop需要特殊实现。
    • 一个绑定窗口一次只能渲染一个地方，如果要渲染2个地方，就要创建2个实例。
    • list绑定窗口的例子：sample目录下的ListBindWnd。
    • tree绑定窗口的例子：sample目录下的TreeBindWnd。
    • rich绑定窗口的例子：sample目录下的RichEdit。
    • ConvertToPic的例子：sample目录下的Win2Pic。

  14. DUI键盘消息
    1. DUI收到键盘消息后，首先以CM_APPMESSAGE分发给MessageFilter,用户可以用_tuiApp.AddMessageFilter来拦截消息。
    2. 然后消息进入实体窗口的WindowProc,用户可以在dialog上用BEGIN_MSG_MAP拦截消息。
    3. 消息发送给当前focus控件。(分发给MessageFilter,然后route,然后WidgetProc)。
    4. 用户可以拦截focus控件收到消息并自己处理回车、tab、箭头、esc、加速键。此时设置bhandle=true可以中断消息传递。
    5. DUI控件处理完key消息后，会向父控件发送CM_MSGBUBBLE消息，这个就是DUI的冒泡机制。冒泡的意思是会向父控件转发，直到mgr窗口。
    6. mgr收到冒泡消息后会处理默认键盘事件，比如tab和箭头键会切换focus控件，回车键会发送IDOK，ESC键会发送IDCANCEL，加速键会发送相应COMMAND消息。
    7. 如果当前对话框没有focus控件，那么键盘消息会直接以CM_MSGBUBBLE发送到mgr窗口上。
    8. 如果想事先拦截当前窗口的键盘消息，可以使用ROUTE_HANDLER。
    9. 如果想事先拦截所有窗口的键盘消息，可以使用MessageFilter。

  16. 定制光标形状
    17. 与Windows标准不同，DUI的WM_SETCURSOR是在CM_MOUSEENTRY后发送的，而且只发一次，直到鼠标进入另外一个控件。
    响应WM_SETCURSOR->调用SetCursor->return 1。就能定制控件光标。
    如果想在同一个控件内设置不同的光标，比如左边超链接右边箭头，可以拦截WM_SETCURSOR，同时在WM_MOUSEMOVE中SetCursor。

  18. 避免重复加载字串表
    19. DUI可以提取rc中的字符串表到语言包中。
    在这种情况下，编译出来的exe中就会产生2份字符串表：一份是rc编译出来的，一份写在xml中的，造成了不必要的重复。
    为了避免这种情况发生，可以如下处理rc文件：
    1. 假设原来的默认语言是英语（ENU）。
    2. 用VC打开资源，在string table上右键属性，然后选择一个其他的语言，比如韩语。
    3. 在VC工程设置里选择资源选项，在预处理定义中加入宏：AFX_RESOURCE_DLL,AFX_TARG_ENU。
    4. 指定英语的rc编译出来后不带韩语字串表，又可以被DUI导出，完美解决问题。

  19. 高对比度模式下的行为

    20. 几个相关的style:
    SS_WINDOWBKONHC 高对比度下显示COLOR_WINDOW
    SS_DLGBKONHC 高对比度下显示COLOR_BTNFACE
    SS_CLEARBKONHC 高对比度下用RGBA(0,0,0,0)清除背景
    SS_NULLBKONHC 高对比度下不画背景
    SS_NULLBKONNORMAL 正常情况下不画背景
    无 高对比度下画bkpic

    控件行为:
    对象 背景 前景
    Frame; Sys; GroupBox 系统
    PushButton; TabButton; ComboButton 系统 无影响
    Widget; Dummy; ActiveX; ScrollBox; Video COLOR_3DFACE
    MenuBar COLOR_3DFACE 系统
    Rich; Edit; Memo COLOR_WINDOW
    Tree; ListBox COLOR_WINDOW 系统
    Window; Static; Float; Arrow 用户指定
    Splitter COLOR_SCROLLBAR
    CheckBox; RadioButton 透明 系统
    Animate 无影响
    Progress; TrackBar; UpDown 无影响 无影响
    上述表格的前提是设置了前景pic和背景pic，无pic则忽略上述行为。
    高对比模式下的颜色值详情，请查看CAppColor(atcolor.h)。
    DUI bitmap有一个属性MonochromeOnHC，勾上后可以在高对比度模式下把位图颜色按像素alpha值改成当前的文字颜色。
    算法: dest.R = 字.R * 图.A; dest.G = 字.G * 图.A; dest.B = 字.B * 图.A; dest.A = 图.A;（字的RGB由系统决定）
    这个模式仅适用于线框模式的图，不适用于色块模式的图。
    色块模式的图在高对比度下有可能跟背景色无法区分，所以色块图在设计的时候就应该用其他颜色描边。
    小技巧：
    • 如果一个PushButton的需求是正常状态无背景，高对比度要求显示成标准按钮，可以把bkpic设置成IDP_PRE_PIC_NULL。
    • 如果一个半透明窗口的需求是正常状态有阴影，高对比度要求显示正常对话框，可以把bkpic设置成阴影，但是frame里的pic设置成DP_PRE_PIC_NULL。
    • 如果一个edit要求正常状态有4态边框，高对比度下变成正常边框，可以把bkpic设置成4态边框，但是frame里的pic设置成DP_PRE_PIC_NULL。

  20. 颜色
    21. DUI颜色属性同时支持色彩模式、索引模式、默认模式、继承模式。
    色彩模式为预乘ARGB。例如:alpha为0xF0的白色值为0xf0f0f0f0，而不是0xf0ffffff。
    索引模式为windows预定义的COLOR_XXX宏，用户可以用ColorFromSys()来取得实际的颜色值。
    默认模式表示使用控件默认颜色。
    继承模式表示使用父控件当前的颜色，继承模式支持高对比度，其他都不支持。
    TMColor除了RGBA(0,0,0,0)外，不能使用其他alpha为0的颜色，比如RGBA(255,255,255,0)，可以用RGBA(255,255,255,1)代替。
    索引与继承模式会忽略高对比度。也就是说，在高对比下，这两种模式使用用户配置，不用系统配置。
    案例1：button设置成索引色可以模拟hyperlink的效果。
    案例2：static成为button的子窗口并且设置成继承可以让文字颜色与button同步。

  21. 动态换肤及暗黑模式
    1. DUI有三大方法可以实现动态换肤：
      1. 用_tuiApp.LoadXml的第3个参数加载皮肤。具体例子可以参考sample目录里的SkinLanguage。维护繁琐，不推荐。
      2. 动态调用函数设置对象颜色，背景等。维护麻烦，不推荐。
      3. 使用_tuiApp.SetColorTransform函数：推荐。
      // 这是DUI编辑器实现暗黑模式的代码，这种方法相对简单。
void SetDark(ATBool bUIDark)
{
    // TM::CColorTransformDark为DUI内置的dark类，作用是反转颜色值。
    struct CDarkStyle : public TM::CColorTransformDark
    {
        virtual TMColor ConvertColor(ATLParam context, TMColor clr) at_override
        {
            // context为颜色拥有者的object id，可以是pic，frame或window。
            if (context == IDC_CLR_TOOLBAR || context == IDP_GRADIENT_10003)
                return TMRGB(0,0,0);
            else if (context == IDO_DUI_MENUBAR_10004 && clr != TMRGB(255,255,255))
                return clr;
            return CColorTransformDark::ConvertColor(context, clr);
        }
    };
        
    static CDarkStyle style;
    _tuiApp.SetColorTransform(_Module.m_hInstResource, bUIDark ? &style : 0);
}
    2. 调用SetColorTransform后，当前module的所有窗口都会收到CM_USERINTERFACE消息。
    3. 把Pic对象的Valid::ColorTransform属性勾上后就可以启用Pic的色彩转换。否则Pic在dark模式里维持原样，不会转换颜色。
    4. 点击DUI编辑器工具栏上的"Test - High contrast/Dark mode"可以实际观察测试对象的效果。
    5. DUI编辑器菜单View->Dark Mode可以把编辑器设置成暗黑模式。
    6. 以上3种方法可视需求自由组合使用。

  22. 支持读屏软件
    1. DUI所有窗口role默认都是window。
    2. 系统主窗口role应该设置成application。
    3. 对话框role应该设置成dialog。

  23. SVG动画限制
    1. 不支持任何滤镜。(阴影可用渐变代替)
    2. 不支持文字。(可用path代替)
    3. 不支持嵌入图像。
    4. 不支持mask,clip。(可改变物体Z顺序或建一个遮挡物体代替)
    5. 不支持属性animation_delay,animation_iteration_count,animation_direction,animation_fill_mode。
    6. 不支持<animateMotion><animateColor>。(可用CSS @keyframes代替)
    7. <animateXXX>属性只支持attributeName,type,from,to,dur,keyTimes,values。
